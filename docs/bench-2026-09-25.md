# Bench session 2026-09-25: live-CV fixes confirmed, GUI start/lock fixes, spectra gaps

This is the handoff for a session continuing **away from the rig**. The work was done on
the PGSTAT302N + AvaSpec-ULS2048L rig, entirely on the **10 kOhm dummy resistor** (no film).
The detail for the live-CV part is in §7 of
[`live-cv-findings-2026-09-24.md`](live-cv-findings-2026-09-24.md); this page is the summary.

## 1. Confirmed on the instrument

- **The wedge is gone.** The fix (`7b9da23`) draws the live CV from the recorder (`.Signals`).
  The user watched the live trace on every CV today (four runs) and saw no wedge.
- **No point at the origin.** The CVs dropped 1–3 samples from before the latch loaded.
  The chrono files kept every row: 301 or 151 per segment, as requested.
- **The chrono axis is readable.** On 2026-09-25 the live chrono axis read
  "1e-9+3.027e-5" on a flat 30 uA hold. The fix holds the y-span to at least 10% of
  |y|, and the user confirmed it on the rig (`20260925_test4`).

## 2. Code changed today (all tested and confirmed at the rig)

| Change | Where |
|---|---|
| A single failed live read of the recorder is expected and skips one frame. A WARNING now appears only after `LIVE_READ_WARN_AFTER` = 5 consecutive failures. The old message claimed the trace would stay blank, which was never true. | `potentiostat.py::_recorder_snapshot` |
| The live plot's minimum y-span is `LIVE_MIN_Y_SPAN_FRAC` = 0.10. Only the view changes, never the data. | `plot_canvas.py::_widen_flat_y` |
| The Run tab lists the **planned** sequence, with the potential for each step, rebuilt every time the tab comes forward. Before, it was filled only at Start. | `run_tab.py::refresh_plan` |
| Start asks "Start this run?" and summarises the folder, sample, segment count, CV and doping ranges, and the chrono current range. A blank sample name or a folder that is only the date prefix is called out, not refused. Cancel is the default. | `run_tab.py::_confirm_start` |
| The Parameters tab is locked while a run is going, with a yellow note. It still scrolls and Save still works. | `parameters_tab.py::lock_for_run` |

**Why the last three exist:** a run started with the relaunch defaults: a blank sample
name, folder `20260925_`, and doping up to +0.8 V. The Run tab's list, then filled only
at Start, was read as "the plan". Edits made on Parameters afterwards were accepted
silently and never reached the run. How Start got pressed is unknown, because button
clicks are not logged.

## 3. Measured on the dummy (`20260925_test2`, `20260925_test4`)

- **CV:** R = 9899–9901 ohm. The zero offset was +7 to +11 nA and the residual sd was
  17 nA.
- **`CR11_100uA` chrono holds:** 20.19 uA at +0.200 V and 30.27 uA at +0.300 V, both
  9.9 kOhm, with noise of 1.5–2.7 nA. At 0 V they read about +11 nA, against 1.3–1.6 uA
  on `CR09_10mA`. **The zero offset scales with the range.** This supports running
  films on a lower range.
- **"The measured current never exceeded 1e-7 A … cell probably open" at 0 V is a
  false alarm on a resistor.** A resistor at 0 V draws nothing.
- **During the CV the front panel showed auto-ranging down to 10 uA near 0 V.** That is
  the CV procedure's own ranging, and it produced no steps in the data.
- **One CV (`20260925_`) flagged a CURRENT OVERLOAD at t = 1.1 s, right at cell-on.**
  Its recorded data is clean, so it looks like a range-switching transient. It did not
  happen on the other CVs.
- **`20260925_test1` is not usable for numbers.** An intermittent reference clip gave a
  +40 uA offset and a degraded third cycle. It is valid only as a plotting result.

## 4. OPEN: spectra gaps at the start of every chrono segment

`20260925_test4` has gaps of 260–463 ms in the first ~2 s of **every** chrono segment.
The CV was clean at a maximum of 127 ms. The likely cause is GUI-thread work at the
segment hand-off competing with the acquisition thread for the GIL. The previous
segment's absorbance plot, the Results refresh and the Analysis refresh all run while
the next segment has already started, about 1 s later. Timed offscreen with that run's
data:

| Work at the end of a segment | CV, 721 spectra | Chrono, 151 spectra |
|---|---|---|
| `show_absorbance`: one `Line2D` per spectrum | 1320 ms | 360–410 ms |
| `results_tab.refresh_segments` | 300 ms | 300–630 ms |
| `analysis_tab.refresh_segments` | 620 ms | 690–1070 ms |

**Not proven.** `20260925_test2` ran the same code path and had no gaps. The guess is
that the Run tab was not visible then, and a hidden canvas does not actually draw.
Neither does this explain the 1139 ms stall on 2026-09-24, which was a CV-only run.

**Why it matters:** the timestamps are real, so no data is wrong. But the first 2 s of
a doping step is the transient on a film, and the spectra there come unevenly spaced.

**Proposed fix, not started:**
- Draw the absorbance traces as one `LineCollection`. All traces are kept.
- Refresh Results and Analysis when those tabs are shown or when the run ends, instead
  of after every segment.

**How to verify it on the rig:** sit on the Run tab for one doping/dedoping pair and on
another tab for the next, then compare the cadence lines.
